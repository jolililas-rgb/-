# Бот учёта операций обменного пункта

Telegram-бот для операторов обменки: фиксация **доходов** (сделок) и **расходов**, запись в Google Таблицу, публикация доходов в канал и регулярные отчёты.

## Почему Telegraf v4

Telegraf 4 — зрелый стек для Telegram Bot API: middleware, сессии, удобные `action`/`hears`, стабильный API без ломки контракта v3. Для пошагового мастера (доход/расход) этого достаточно: состояние держим в session, без тяжёлого фреймворка. Сцены (Scenes) при желании можно добавить поверх той же сессии.

Сессии сейчас **in-memory**. Интерфейс хранилища (`get` / `set` / `delete`) вынесен в `src/utils/session.js`, чтобы позже подставить Redis без переписывания хендлеров.

## 1. Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. Создайте канал для публикации доходов, добавьте бота **администратором** с правом писать сообщения.
3. Узнайте ID канала (`TELEGRAM_CHANNEL_ID`): для публичного канала это `@name`, для приватного — число вида `-100...`.
4. Узнайте user ID операторов (например, через `@userinfobot`) и пропишите их в `TELEGRAM_ALLOWED_USER_IDS`.
5. ID получателей вечерних отчётов — в `TELEGRAM_REPORT_USER_IDS`. Эти люди должны хотя бы раз написать боту `/start`, иначе Telegram не даст отправить им сообщение.

Кто не в белом списке, получает «Доступ запрещён»; дальше бот их апдейты не обрабатывает. Паролей нет.

## 2. Google Таблица и Service Account

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте проект (или выберите существующий).
2. Включите **Google Sheets API**.
3. **IAM и администрирование → Учётные записи служб → Создать**:
   - роль можно не назначать на проект;
   - создайте ключ JSON (**Ключи → Добавить ключ → JSON**).
4. Сохраните файл как `service-account.json` в корне проекта (путь задаётся `GOOGLE_SERVICE_ACCOUNT_JSON`). **Не коммитьте его в git.**
5. Создайте Google Таблицу. Из URL скопируйте ID:  
   `https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/edit`
6. Откройте JSON ключа, найдите `client_email`. В таблице: **Настройки доступа → Добавить** этот email с правом **Редактор**.
7. Листы «Доходы» и «Расходы» бот создаст сам при старте и проставит заголовки. Можно создать их вручную — имена должны совпадать точно.

### Лист «Доходы»

Оператор | Дата и время | Номер сделки | Имя | Username | Сумма приема в fiat | Сумма приема в USDT | Сумма выдачи в USDT | Сумма выдачи в fiat | Курс закупа usdt | Курс закупа fiat | Заработанный процент | Прибыль в USDT | Комментарий

Дата: `DD.MM.YYYY HH:mm` (Москва). Номер сделки сквозной: `(число строк данных) + 1` в момент «Верно».

### Лист «Расходы»

Оператор | Дата и время | Категория | Сумма в USDT | Комментарий

Расходы в канал **не** публикуются.

## 3. Переменные окружения

```bash
cp .env.example .env
```

Заполните:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_CHANNEL_ID` | Канал для сделок дохода |
| `TELEGRAM_REPORT_USER_IDS` | ID получателей отчётов через запятую |
| `TELEGRAM_ALLOWED_USER_IDS` | Белый список операторов |
| `GOOGLE_SPREADSHEET_ID` | ID таблицы |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Путь к JSON ключу, по умолчанию `./service-account.json` |
| `TIMEZONE` | `Europe/Moscow` |
| `DAILY_REPORT_CRON` | Ежедневно 23:58 МСК: `58 23 * * *` |
| `WEEKLY_REPORT_CRON` | Воскресенье 23:59 МСК: `59 23 * * 0` |
| `CYCLE_START_DATE` | Старт 28-дневного цикла, `YYYY-MM-DD` |
| `LOG_LEVEL` | `info` / `debug` / … |

## 4. Запуск локально

Нужен **Node.js 18+** (лучше 20 LTS).

```bash
npm install
npm test
npm start
```

Положите `service-account.json` и заполненный `.env` в корень.

## 5. Docker

В контейнер монтируйте секреты, не копируйте их в образ:

```bash
docker build -t exchange-bot .
docker run --rm \
  --env-file .env \
  -v "%cd%/service-account.json:/app/service-account.json:ro" \
  exchange-bot
```

На Linux/macOS том: `-v "$(pwd)/service-account.json:/app/service-account.json:ro"`.

В Docker `NODE_ENV=production`, логи — JSON (pino). Часовой пояс отчётов задаётся `TIMEZONE=Europe/Moscow` в cron (`node-cron`), а не TZ контейнера, но для ясности можно добавить `-e TZ=Europe/Moscow`.

## 6. Как работает бот

Главное меню: **Доход** / **Расход**.

**Доход:** оператор → валюта и суммы приема → валюта и суммы выдачи → имя / username / комментарий (можно «Пропустить») → проверка → «Верно» или «Изменить».

Схема: fiat → USDT → fiat (USDT может быть и приёмом, и выдачей).

Расчёты (округление до 2 знаков):

- курс закупа приёма = сумма_приема_в_валюте / сумма_приема_в_USDT (пусто, если приём = USDT);
- курс закупа выдачи = сумма_выдачи_в_валюте / сумма_выдачи_в_USDT (пусто, если выдача = USDT);
- прибыль USDT = приём USDT − выдача USDT;
- процент = прибыль / выдача USDT × 100.

Повторное «Верно» блокируется флагом в сессии. Номер сделки берётся под mutex, чтобы два оператора не получили один номер.

**Расход:** оператор → категория → сумма USDT → комментарий → подтверждение → только таблица.

## 7. Рассылки (МСК)

Метрики за период по листу «Доходы»:

- **ДОХОД** — сумма прибыли USDT;
- **ОБОРОТ** — сумма приема в USDT;
- **З/П АЛИ / АНЯ / ЮЛЯ** — 10% прибыли сделок соответствующего оператора.

1. Ежедневно **23:58** — за текущие календарные сутки.
2. Воскресенье **23:59** — неделя с понедельника 00:00 по воскресенье.
3. Воскресенье **23:59**, если с `CYCLE_START_DATE` прошло ровно 28×k дней (k ≥ 1) — отчёт за этот 28-дневный интервал.

